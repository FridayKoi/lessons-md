# 查阅错题本，先看前人怎么死的

本项目维护着一本错题本 `LESSONS.md`（项目根目录），记录了 AI 在这个项目里踩过的坑。你的职责是确保同样的坑不再踩第二次。

## 什么时候读

1. **会话开始、接到第一个任务时**：通读 `LESSONS.md` 全部条目。文件很小（设计上 < 200 行），整读没有负担。
2. **准备执行某个操作前**：如果该操作与任何条目的"触发场景"匹配（关键词、任务类型、命令模式），先重读那几条，再动手。
3. **任务中途偏离原计划时**（换方案、换工具、换命令）：重新过一遍触发场景——换路线往往正是踩坑高发点。

## 怎么用

- 🟡 **建议条目**：匹配到触发场景时，按"✅ 正确做法"执行。
- 🔴 **禁令条目**：硬性约束。如果你发现自己正准备做条目"❌ 错误做法"里的事——**立即停下**，改按"✅ 正确做法"执行，并向用户说明一句："错题本 E-0XX 禁止这样做，原因是……"。
- **命中一条就读整族**：条目带 `- 同族: E-XXX` 时，把族内条目一并重读——族内条目是同一根因的不同表现面，只防住其中一面等于没防。若族内条目含"族则"（加粗的通用规律），按族则执行而不是只按单条的 ✅。
- 如果按建议做法执行**仍然失败**了，照实告诉用户——这可能是条目过时或场景特殊，不要为了"遵守错题本"而掩盖失败。失败会在下次 `/retro` 复盘时被记录。

## 边界

- 错题本与 `CLAUDE.md` / `AGENTS.md` 冲突时，以 `CLAUDE.md` / `AGENTS.md` 为准，并向用户指出冲突。
- 错题本条目明显不适配当前场景时（比如条目针对的开发环境与本机不同），不要机械套用，向用户确认。
- 找不到 `LESSONS.md` 时：什么都不做，正常继续任务。本项目可能还没启用错题本。
