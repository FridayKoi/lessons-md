# 复盘会话，维护错题本

你的任务是从当前会话中提炼错误模式，合并进项目根目录的 `LESSONS.md`。错题本只记**错误模式**，不记流水账——一条条目必须能让下一个新会话的 AI 避免重蹈覆辙。

## 第一步：收集候选

从当前会话历史（如可用，也可读取会话记录文件，如 Claude Code 的 `~/.claude/projects/<项目目录>/*.jsonl`）中找出以下信号：

1. **用户纠正**：用户明确指出 AI 做错了、要求重做或改变方向
2. **重复失败**：同一操作失败 2 次以上才成功（重试、换命令、改参数）
3. **浪费型弯路**：花了大量轮次排查、最后发现是低级错误（如改错了文件、没先确认环境）
4. **回滚**：做了改动又撤销

没有被用户纠正、也没造成浪费的一次性小失误，**不要**收录——错题本贵在少而准。

## 第二步：去重与合并

读取项目的 `LESSONS.md`。若不存在，在项目根目录创建它，内容如下（此 skill 的安装目录里没有模板文件，必须用下面内嵌的内容自举）：

```markdown
# 项目错题本 / Mistake Notebook

> 本文件由 /retro（mistake-retro skill）维护，人工也可以直接编辑——人类编辑优先。
>
> **AI 必读**：开始任何任务前，先通读本文件全部条目；准备执行的操作与某条目的"触发场景"匹配时，必须先重读该条目并按"✅ 正确做法"执行。🔴 禁令条目为硬性约束，无例外。

## 统计

- 条目数：0
- 最近更新：YYYY-MM-DD

## 条目
```

对每条候选，与现有条目逐一比较。**判定为同一条**的标准：触发场景和错误做法实质相同（措辞不同没关系）。合并规则：

- **命中已有条目**：`复发` 计数 +1，并在括号内的日期列表末尾追加本次日期（格式：`复发: 3 次（09-10, 09-15, 09-17）`；只记月-日，跨年时该日期写全年份）。若计数达到 **3**，把等级从 🟡 建议 升级为 🔴 禁令，并在条目末尾追加一行 `- 升级: YYYY-MM-DD 第3次复发，升级为禁令`。如果本次会话揭示了更好的"✅ 正确做法"，更新它。
- **新错误**：在"条目"区末尾追加新条目，ID 按现有最大号递增（不复用已删除的 ID），等级 🟡 建议。
- **同族但不同面**（同一根因、同一容器/场景，但错误做法和修法不同——如"撑高行"与"挤宽行"）：新建更具体的条目，同时做两件事：①新旧条目互加一行 `- 同族: E-XXX`；②重读族内老条目的"✅ 正确做法"，把本次揭示的更通用规律合并进去——族内规则要覆盖整个家族，不能只覆盖各自第一次翻车的那种做法。

## 第三步：收尾

1. 更新文件顶部"统计"区：条目数、最近更新日期
2. 向用户输出简要变更摘要，格式：

```
错题本更新：
- [E-002] 修改构建配置前先确认构建方式 —— 复发 +1（2 次），仍是 🟡
- [E-004] 新增：部署前先跑 lint —— 🟡 建议
```

## 写条目的要求

- 标题用**祈使句**，直接说结论（"禁止 X"、"做 Y 之前先 Z"），不用疑问句或描述句
- "触发场景"要写**具体可匹配的信号**（涉及什么任务、什么命令、用户提到什么词），这是 AI 新会话里能否想起这条的关键
- "❌ 错误做法"写清当时为什么这样做——知道错误动机才能防止再犯
- "✅ 正确做法"必须**可执行**，最好含命令或代码，不写空话（"要小心"是废话）
- 一条条目控制在 10 行以内，超了说明粒度太细，拆开或合并
- 可选字段 `- 同族: E-XXX`：标记同根因、不同修法的关联条目（新旧双方都要加）；查阅端命中族内一条时会连带读整族

## 人工编辑优先

如果发现 `LESSONS.md` 被人工修改过（条目被删除、改写、标注"过时"），尊重人工编辑：被删除的条目若再次触发，作为新条目重建并注明"曾于 X 日人工删除"。条目被标注"过时"或"作废"的，跳过不再恢复。
